## 一条曲线交叉引发的争论

2025 年初，DeepSeek-R1 让 RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习）成了提升推理能力的默认答案。RLVR 的设定很简单：模型输出答案，一个确定性的验证器（数学题比对标准答案、代码题跑单元测试）返回 0 或 1 的奖励，用策略梯度优化。因为奖励可以自动算，这条路线不需要人工标注，看起来可以无限 scale。

社区当时的主流叙事是类比 AlphaGo：传统 RL 让智能体在自我博弈中发现人类没想到的策略，RLVR 应该同样让 LLM 自己长出反思、枚举、回溯这些新的推理模式，突破 base model 的天花板。

这篇论文做的事是把这个叙事拿去做一个具体的测量：如果 RLVR 真的扩展了能力边界，那么它应该能解出 base model 解不出的题。作者把评测指标从 pass@1 换成大 $k$ 的 pass@k，得到的结果是一条反直觉的曲线——

![Figure 1 左](/assets/images/rl-beyond-base-model/x1.png)
*Figure 1（左）：论文对现象的示意。四棵树是同一道题上反复采样得到的搜索树，左列是 base model、右列是 RLVR 模型；黑色边表示有较高概率被采样到的路径，灰色表示几乎采不到，叶子上的 0 / +1 是验证器给的奖励（绿色 +1 是正确解）。上排 Problem A（箭头向右，"更高效的采样"）：base 的黑色路径散布在大量 0 上，RLVR 后只剩通向两个 +1 的路径是黑的。下排 Problem B（箭头向左，"推理能力范围收缩"）：base 有一条黑色路径通到 +1，RLVR 后这个 +1 变成灰色（采不到了），黑色路径都通向 0。*

![Figure 1 右](/assets/images/rl-beyond-base-model/x2.png)
*Figure 1（右）：横轴是采样次数 $k$（对数轴，1 到 256），纵轴是 pass@k，即"$k$ 次尝试内至少解对一次的题目比例"。黑色是 base model Qwen2.5-7B，紫/绿/黄依次是 GRPO 训练 150/300/450 步的模型。训练步数越多，$k=1$ 处越高（0.10 → 0.26 → 0.34 → 0.42），但 $k=256$ 处的排序完全反过来（黑线约 0.67 反超所有 RL 曲线）。四条曲线在 $k$ 约 64–128 之间交汇。*

一句话总结论文的结论：当前的 RLVR 主要在做的事是把概率质量搬到已经存在的正确路径上（采样效率提升），而不是产生新的正确路径；而且这个搬运过程会让一部分原本能采到的正确路径变得采不到（覆盖收缩）。

这篇论文在 2025 年被大量引用，也被大量反驳。笔记的后半部分会专门处理两个我认为最要紧的质疑：base model 在这些 benchmark 上的"能力"有多少是背下来的，以及 T=0.6 / top-p=0.95 这一组采样参数是否公平。

## 为什么换成 pass@k

先说清楚这个指标，因为全篇的结论都建立在它身上，而它也是争议的核心。

给定一道题，从模型采样 $k$ 个输出，只要有一个通过验证器就记为解出。整个数据集上的平均 pass@k 表示"$k$ 次尝试内模型有可能解出的题目比例"。$k=1$ 就是常规的平均准确率。

作者用了 Chen et al. 的无偏低方差估计量：对每道题采 $n \ge k$ 个样本，其中 $c_i$ 个正确，则

$$\text{pass@}k := \mathbb{E}_{x_i \sim \mathcal{D}}\left[1 - \frac{\binom{n-c_i}{k}}{\binom{n}{k}}\right]$$

括号里那一项是"从 $n$ 个样本里抽 $k$ 个、全都抽到错误样本"的概率，1 减去它就是至少抽到一个正确的概率。这样一次采样 $n$ 个就能同时估计所有 $k \le n$ 的 pass@k，比"真的只采 $k$ 个"方差小得多。实验里 $n$ 取曲线最右端的 $k$，一般是 128、256 或 1024。

论文特意区分了 pass@k 与 Best-of-$N$、majority voting：后两者衡量的是"能不能可靠地把正确答案挑出来"，是实用指标；pass@k 衡量的是"正确答案在不在模型的采样分布里"，是能力边界的指标。作者要问的是后者。

**数学题的猜答案问题。** 代码题跑单元测试，蒙对概率可以忽略。数学题不行——AIME 的答案是 0 到 999 的整数，$k=1024$ 次采样下瞎猜也可能撞上，而且模型可能给出错误的 CoT 却得到正确答案。作者做了两层处理：

一是人工检查。对 GSM8K 中平均准确率在 0% 到 5% 之间（即最难但非零）的题目，逐条看导致正确答案的 CoT 是否真的成立。base model 解出 25 道，其中 24 道至少有一条正确 CoT；RL 模型解出 25 道，23 道至少有一条正确 CoT。视觉推理任务上抽查最难的 8 道题，两个模型都是 7/8 有正确 CoT。

二是过滤"可猜"的题。让 Qwen2.5-7B-Base 不用 CoT 直接答题、多次采样，如果一道题能以低但非零的概率（<5%）答对，就认为它可猜并剔除。AIME24 的 30 道题过滤后剩 18 道，在这个子集上 pass@k 曲线的交叉现象依然存在。然后在这 18 道里再看最难的（平均准确率 <5%）：base model 解出 7 道，其中"6 道里有 5 道"包含正确 CoT（剔除了一个因为跳步而难以判定的模糊案例）；RL 模型解出 6 道，4 道包含正确 CoT。这里的 7 与 6 对不上，v1 与 v5 逐字相同，一年五个版本都没改，我没能确定哪个是笔误。

作者还主动提了一个 caveat：如果 $k$ 大到天文数字，即使在词表上均匀随机采样也终会撞出正确路径。他们的辩护是 base model 在 $k=128$ 或 $1024$ 这种现实可承受的量级上就已经能答对。但直到 v5（2025 年 11 月），全文都没有加入一个随机采样的对照组——"能力边界"的下界始终没有被量化。

## 三个领域，同一个形状

实验规模是这篇论文被广泛引用的一个原因。数学任务用 zero-RL 设定（直接对 base model 做 RL，不经 SFT），代码和视觉推理任务因为纯 zero-RL 不稳定，按社区惯例从 instruct 模型起步、和其 RLVR 版本对比。

| 任务 | 起始模型 | RL 来源 | Benchmark |
|------|---------|---------|-----------|
| 数学 | Qwen2.5-7B/14B/32B-Base、Qwen2.5-Math-7B、LLaMA-3.1-8B | SimpleRLZoo、Oat-Zero、DAPO（GRPO） | GSM8K、MATH500、Minerva、Olympiad、AIME24、AMC23 |
| 代码 | Qwen2.5-7B-Instruct-1M、DeepSeek-R1-Distill-Qwen-14B | Code-R1、DeepCoder（GRPO） | LiveCodeBench v5、HumanEval+、MBPP+ |
| 视觉推理 | Qwen2.5-VL-7B | EasyR1（GRPO），在 Geometry3K 上训练 | MathVista、MathVision（去掉选择题） |
| 深度分析 | Qwen2.5-7B-Base 等 | VeRL 自训（PPO/GRPO/Reinforce++/RLOO/ReMax/DAPO） | Omni-MATH-Rule、MATH500 |

评测协议里有两个值得记住的选择。第一，采样统一用 temperature 0.6、top-p 0.95、最长 16384 token。第二，评测 base model 时**不用 few-shot**。这是反常规的——通常评 base model 会给几个示例来引导格式。作者的理由是 in-context 示例本身会引入推理上的混淆效应，为了公平就让 base 和 RL 模型用完全相同的 zero-shot prompt（即 RLVR 训练时用的那个 prompt）。作者提到，base model 在没有 few-shot 引导时经常输出格式混乱甚至无意义的内容，但采样次数足够多时仍然能产出格式正确并解对的回答。

![Figure 2](/assets/images/rl-beyond-base-model/x3.png)
*Figure 2：四列是四个模型（Qwen2.5 的 7B/14B/32B 和 LLaMA-3.1-8B），四行是四个 benchmark（AIME24、MATH500、Minerva、Olympiad）。每个子图里绿色是 base，粉色是 RL。三个 Qwen 列的形状高度一致：粉线在左端高出一截，绿线斜率更大，交叉发生在 $k$ 约 4 到 128 之间，之后绿线在上。以 32B 在 Minerva 为例，$k=128$ 处 base 约 0.68、RL 约 0.58，差约 9 个百分点，即能多解出约 9% 的题。最右列的 LLaMA-3.1-8B 是例外，后面会回来讨论：AIME24 上两条线几乎重叠在 0.3 以下、看不出交叉，MATH500 和 Olympiad 上交叉发生得很晚（$k$ 约 32 和 256）。*

## 收缩到哪去了：三层证据

上面的曲线只说明"$k$ 大了 base 会赢"，还不能说明为什么。论文用三个递进的分析来定位原因。

**第一层：准确率分布。**

![Figure 5](/assets/images/rl-beyond-base-model/x7.png)
*Figure 5：Qwen2.5-7B 在 Minerva 上的准确率直方图。横轴把每道题的平均准确率分成 11 个区间，纵轴是落在该区间的题目数（左轴频数、右轴百分比）。青色是 base，粉色是 RL。RL 让最右端（0.9–1.0）的题目数从个位数涨到 46，让中间低准确率区间（0.1–0.5）大幅变薄——这是采样效率提升。但最左端"准确率恰好为 0"的柱子，RL（约 113）比 base（约 93）更高。*

准确率 0 意味着采 $n$ 次一次都没对，也就是这道题从"偶尔能解"变成了"完全不能解"。这一根柱子解释了平均分提升的来源：不是解出了新题，而是把已经会的题做得更稳，代价是一批边缘题被推到了零。

**第二层：可解题集合的包含关系。**

| Base | RL (SimpleRLZoo) | AIME24 ($k$=1024) | MATH500 ($k$=128) |
|------|------------------|-------------------|-------------------|
| ✓ | ✓ | 63.3% | 92.4% |
| ✓ | ✗ | 13.3% | 3.6% |
| ✗ | ✓ | **0.0%** | **1.0%** |
| ✗ | ✗ | 23.3% | 3.0% |

第三行是关键：AIME24 上不存在任何一道"base 解不出而 RL 能解出"的题；MATH500 上有 1%（约 5 道），但作者补充说这 5 道在 base model 采样 1024 次时全部能解出。也就是说 RL 可解集近似是 base 可解集的子集。附录给了 AIME24 的具体题号——base 能解 23 道，RL 能解的 19 道全在这 23 道里面。代码任务上是同样的趋势，LiveCodeBench 第 400–450 号题里 Coder-R1 独有的只有一道（430 号）。

**第三层：困惑度。** 集合层面的包含还留了一个漏洞——也许 RL 模型走的是全新的推理路径，只是恰好解出了同一批题。要排除这个可能，需要看路径本身在不在 base 的分布里。作者用困惑度：

$$\text{PPL}_m(\mathbf{Y} \mid x) = \exp\left(-\frac{1}{T}\sum_{t=1}^{T}\log P(y_t \mid x, y_1, \dots, y_{t-1})\right)$$

即模型 $m$ 对给定回答 $\mathbf{Y}$ 的平均负对数似然取指数。PPL 越低说明 $m$ 越有可能自己生成出这个回答。

![Figure 6](/assets/images/rl-beyond-base-model/x8.png)
*Figure 6：两道 AIME24 题目上的困惑度箱线图，左右各一道。四组从左到右：base 对自己回答的 PPL（青，分布最宽）、base 对 RL 模型回答的 PPL（粉，落在青色分布偏低的那一段）、RL 对自己回答的 PPL（黑，接近 1.0）、base 对 OpenAI-o1 回答的 PPL（紫，明显高出一截）。*

粉色落在青色分布的下半部分——RL 模型生成的回答，正是 base model 本来就倾向生成的那一类。作为对照，紫色（o1 的回答）对 base 来说困惑度显著更高，说明这个指标确实能区分"分布内"和"分布外"的路径。附录 C.4 还给了训练过程中的演化：随 RL 训练推进，$\text{PPL}_{\text{Base}}(\mathbf{Y}_{\text{RL}})$ 持续下降，即 RL 是在 base 的先验内部不断收窄分布，而不是向外扩张。

## 蒸馏是另一回事

如果 RLVR 被 base 的先验困住，那注入一个更好的先验会怎样？

![Figure 7](/assets/images/rl-beyond-base-model/x9.png)
*Figure 7：Minerva 上四条曲线。青色 Base（Qwen2.5-Math-7B）、粉色 RL（Oat-Zero）、紫色 Instruct、黑色 Distill（DeepSeek-R1-Distill-Qwen-7B，把 R1 蒸馏进 Qwen2.5-Math-7B）。黑线在整个 $k$ 范围内都显著高于青线，没有交叉点。粉线和紫线则是熟悉的形态——左端高、右端被青线追上。*

蒸馏的数据是教师模型生成的长 CoT 轨迹，携带了 base model 分布里没有的模式，所以能真正把边界往外推。RLVR 的正样本全部来自策略自身的采样，能推的只有分布内的概率质量。这个对比构成了论文机制解释的经验支撑。

## 六种算法，差不多的位置

既然 RL 的作用是提升采样效率，作者定义了**采样效率差距** $\Delta_{\text{SE}}$：RL 模型的 pass@1 与 base 模型的 pass@256 之差（把后者当作可达上界的代理）。越小越好。

这个定义本身包含了一个立场：论文把 base model 的 pass@256 当成"理想的 RL 应该达到的 pass@1"。

在 VeRL 框架下统一复现六种算法（去掉 KL 项、学习率 $10^{-6}$、prompt batch 256、每 prompt 8 个 response、最长 8192 token、温度 1.0），训练集是 Omni-MATH-Rule 的 2000 条，同分布测试集 821 条，MATH500 作为分布外测试。

![Figure 8 上](/assets/images/rl-beyond-base-model/x10.png)
*Figure 8（上）：六种算法（GRPO/PPO/ReMax/RLOO/Reinforce++/DAPO，各色）与 base（青）的 pass@k 曲线。虚线是 base 的 pass@256 水平线，双箭头标出的 $\Delta_{\text{SE}}$ 在训练集上 0.359、同分布测试集 0.410、MATH500 上 0.206。所有彩色曲线在 $k=256$ 附近全部挤在青线附近或以下。*

| 模型 | Omni-Test pass@1 | Omni-Test pass@256 | MATH500 pass@1 | MATH500 pass@256 |
|------|------------------|--------------------|----------------|------------------|
| Qwen2.5-7B (base) | 10.2 | 69.1 | 34.5 | 96.2 |
| GRPO | 25.1 | 68.3 | 74.4 | 97.2 |
| PPO | 26.8 | 69.2 | 75.2 | 97.2 |
| ReMax | 23.8 | 67.5 | 73.5 | 96.6 |
| RLOO | 28.1 | 69.2 | 75.0 | 97.4 |
| Reinforce++ | 28.0 | 69.7 | 75.4 | 96.8 |
| DAPO | 26.5 | 67.0 | 75.6 | 96.4 |

同分布测试集上 $\Delta_{\text{SE}}$ 从 RLOO 的 42.6 到 GRPO 的 43.9，跨度 1.3 个点——六种算法的差异远小于它们与上界的距离。这是论文一个容易被忽略但很有杀伤力的次级结论：过去一年算法层面的迭代，在"逼近 base model 潜力"这个尺度上几乎是原地踏步。

有意思的是 MATH500 这一列：RL 的 pass@256 全部**高于** base（96.4–97.4 vs 96.2）。分布外的这个数据集上并没有出现收缩。论文正文没有讨论这个反例，但它和 $\Delta_{\text{SE}}$ 在 MATH500 上明显更小（0.206 vs 0.410）是同一件事——MATH500 太容易，base 的 pass@256 已经接近饱和，没有下降空间。

**几个消融。** 训练步数：pass@1 在训练集上从 26.1（step150）→33.6（step300）→42.5（step450）单调上升，pass@256 从 66.3→65.3→64.3 单调下降。Rollout 数 $n$：从 8 增到 32，pass@k 略有提升，且 $n=32$ 在 pass@128 上更高，但最终仍被 base 超过（这一组只训了 220 步，未收敛）。KL 项：加上系数 0.001 的 KL 后 pass@1 与不加 KL 相当，但 pass@128 明显更低——这个结果反直觉，KL 本该把模型拉住不让它偏离 base 太远。

## 熵：论文自己做的那个对照

熵坍缩是最直接的替代解释：RL 训练让输出熵下降，采样多样性变差，$k$ 大时自然吃亏。这跟"能力边界收窄"是完全不同的说法——前者调温度就能补回来。

作者做了两个实验。第一个是直接扫温度：

![Figure 17](/assets/images/rl-beyond-base-model/x22.png)
*Figure 17：三列是 T=0.6/1.0/1.2，两行是 AIME24（$k$ 到 1024）和 MATH500（$k$ 到 128）。绿色 base、粉色 RL。看 base 随温度的变化：AIME24 上 $k=1$ 处从 0.08 掉到 0.02，MATH500 上从 0.62 掉到 0.29；RL 几乎不动（两个数据集都稳定在 0.15 和 0.78 附近）。交叉点随温度右移：AIME24 在 T=0.6 时约 $k=256$ 交叉、T=1.0 时约 $k=512$、T=1.2 时不再交叉；MATH500 在 T=1.2 时也全程无交叉。*

这张图是作者选 T=0.6 的依据：base model 超过 1.0 就开始输出随机不连贯的 token，而 RL 模型对温度不敏感，0.6 是让两者都发挥较好水平的点。同时它也暴露了实验设计的脆弱之处——主结论的方向可以被一个采样超参翻转，而这个超参是作者选的。

第二个实验更严格，把 RL 模型的温度调高到**输出熵与 base 在 T=0.6 时相等**：

![Figure 18](/assets/images/rl-beyond-base-model/x23.png)
*Figure 18：六个 benchmark，每图标题给出 base 在 T=0.6 时的输出熵 $E_{\text{base}}$（AIME24 是 0.47、MATH500 是 0.72 等）。青线是 base (T=0.6)，粉线是 RL (T=0.6)，紫线是升温到熵匹配后的 RL（AIME24 需要 T=1.5，AMC23 需要 T=0.9，MATH500 需要 T=0.85）。紫线普遍略高于粉线，但在 AIME24、MATH500、Minerva、GSM8K 上仍被青线在大 $k$ 处超过。*

作者的结论措辞是克制的：熵降低对边界收窄有贡献，但不能完全解释。我认为这个实验是全文最重要的对照，也是它比同期同类工作更站得住的地方。但它没有回答另一半问题——RL 训练本身用的温度（1.0）、以及训练时的 top-p 设置，是否本来就该更高。这个我放在后面讲。

## 规模：一个偏弱但重要的补充

结论会不会随模型变大而失效？这是最自然的质疑。作者坦白说很多情况下没法做：o1 的 base 不公开；Qwen3-235B 经过 RLVR 和长 CoT SFT 多阶段训练，无法把 RLVR 的贡献单独剥离；R1-Zero 没有托管 API，自建部署在 32k 长度下只有约 50 token/s，pass@k 评测不现实。

退而选了 Magistral-Medium-2506（纯 RL 训练，起点是 Mistral-Medium-3-2505，规模未公开，能力接近 R1），用 40k 上下文查 API：

![Figure 9](/assets/images/rl-beyond-base-model/x12.png)
*Figure 9（AIME24）：粉线 Magistral-Medium (RLVR)，青线 Mistral-Medium-3 (Base)。$k=1$ 处 RLVR 高出约 23 个点（0.68 vs 0.45），随 $k$ 增大差距持续收窄，到 $k=1024$ 处 0.94 vs 0.90。*

![Figure 9（AIME25）](/assets/images/rl-beyond-base-model/x13.png)
*Figure 9（AIME25）：同样的两条线。$k=1$ 处 0.59 vs 0.31，到 $k=1024$ 处两条线交汇在 0.93 附近。*

## 为什么会这样：论文的解释

论文把原因归到语言空间的两个特殊性质上。

**动作空间的规模。** Go 或 Atari 的动作空间是几百个离散动作，语言模型每步在几万到几十万的词表上选择，序列长度上千。RL 算法本来不是为这种规模设计的，从零开始探索根本碰不到奖励信号。

**先验的双刃性。** 正因为探索不可行，RLVR 必须从一个有用的预训练先验出发。而一旦从先验出发，token 级采样能探到的几乎全在先验覆盖范围内；任何显著偏离先验的采样极可能产出无效或无意义的输出，从而拿到负奖励。策略梯度做的事是提高"先验内且有正奖励"样本的似然、压低"先验外且负奖励"样本的似然——两个方向都在把策略往先验内部推。

顺着这个解释，作者提了四个方向：高层抽象空间的探索（如 AlphaEvolve 在程序层面自我演化）、通过课程学习做数据规模化（先在简单子问题上把成功率从零抬到非零，再攻难题）、过程奖励与细粒度 credit assignment、以及多轮 agentic RL（当前 RLVR 局限于单轮，缺少基于反馈的迭代修正和主动收集信息的能力）。

## 一年后的战场

这篇论文 2025 年 4 月上线，最终拿到 NeurIPS 2025 Oral 和 ICML 2025 AI4MATH workshop 最佳论文，同时也成了 2025 年被反驳最多的论文之一。它前后改了五版（v1 2025-04，v5 2025-11），有些修改本身就是对质疑的回应，值得单独说。

**v1 曾经把原因直接归给熵。** v1 的贡献列表里写的是："我们把这归因于 RL 降低输出熵、从而限制探索的倾向"。也就是说，"熵坍缩"这个替代解释最初是作者自己的解释。§4.5 那个熵匹配对照实验（Figure 18）在 v1 里不存在，是后来加的；加进来之后，结论从"归因于熵"改成了"熵有贡献但不足以完全解释"。Magistral 那组规模实验（§4.6）和 DAPO-32B 也是 v1 之后才有的。这条演化线说明作者确实在补对照，但也说明主结论的因果解释在一年里换过一次。

反驳大致分三路。

**第一路：训练不够久、数据不够广。** NVIDIA 的 ProRL（[arXiv 2505.24864](https://arxiv.org/abs/2505.24864)，NeurIPS 2025）直接点名这篇论文（引用编号 [13]），说它的负面结论"可能源于方法学上的局限而非 RL 方法本身的根本限制"，具体两条：一是过度依赖数学这类专门领域，"模型在预训练和后训练阶段都被过度训练过，从而限制了探索空间"；二是 RL 训练过早终止，"通常不超过几百步"。ProRL 训了 2000 步以上、136K 道题横跨数学/代码/STEM/逻辑谜题/指令跟随五个领域，加上 KL 控制和参考策略重置来对抗熵坍缩。

最硬的一条证据是 boxnet——训练时完全没见过的 Reasoning Gym 任务，"base model 完全不具备解决该任务的能力"，而 ProRL 模型能解；同组的 acre 从 5.99 到 58.57，game_of_life_halting 从 3.49 到 52.29（这三个是逻辑谜题类任务，报的是规则验证器给的连续奖励均分，不是 pass@1）。他们还报告了一个负相关，小节标题就叫"起点越弱，ProRL 收益越大"：base model 初始 pass@128 越高，RL 能扩展的边界越少。据此把任务分成三类：Diminish（pass@1 升但 pass@128 降）、Plateau（早期就见顶）、Sustained（持续外扩，主要是代码）。

Diminish 这一类的原文值得完整引:"在某些 benchmark（尤其是数学领域），Nemotron-Research-Reasoning-Qwen-1.5B 表现出相比 base model **下降或不变**的推理容量，与先前工作 [13] 的观察一致。"换句话说，ProRL 在数学上复现了这篇论文的结论，只是认为数学不能代表 RL 的全部。还有一点值得注意：ProRL 的评测用的是 temperature 0.6、top-p 0.95——和这篇论文完全相同的采样参数。所以两者的分歧不在评测温度上，而在训练规模和领域覆盖上。

**第二路：Qwen2.5 的数学能力有多少是背下来的。** 这是我认为最伤的一路，下面单独展开。

**第三路：pass@k 本身是不是好指标。** 微软的 CoT-Pass@K（[arXiv 2506.14245](https://arxiv.org/abs/2506.14245)）把指标改成"答案对**且**推理链对才算通过"，用 DeepSeek-R1-0528-Qwen3-8B 做 CoT 判官、每条判 3 次。在 Qwen2.5-32B vs DAPO-Qwen-32B 上，他们先复现了 pass@K 的交叉，然后发现换成 CoT-Pass@K 后，AIME24 和 AIME25 上 RL 模型在**所有** $k$（直到 1024）都保持显著领先，交叉消失了；而且 AIME2025 上差距最大——他们的解释是 AIME2025 发布时间晚于 base model 的训练截止。但要说清楚的是，交叉在 MATH-500 和 AMC23 上**没有**消失。另一头，[arXiv 2511.16231](https://arxiv.org/abs/2511.16231) 从梯度层面论证 pass@k 可以做诊断指标但不适合当优化目标。

也有支持这篇论文的理论工作：The Invisible Leash（[arXiv 2507.14843](https://arxiv.org/abs/2507.14843)，Fang Wu、Weihao Xuan、Ximing Lu、Yejin Choi 等）。它的 Theorem C.1（Support Preservation under RLVR）把这篇论文用文字描述的机制写成了形式化结论：on-policy 策略梯度得到的 $\pi_\theta$ 满足 $\text{supp}(\pi_\theta) \subseteq \text{supp}(q)$，因此任何在 base 分布下概率为零的正确解 $y^*$，无论奖励多大都无法被策略梯度触及。

更有用的是它把"扩张"和"收缩"分别量化了。以 ProRL-1.5B 为主要研究对象（起点 DeepSeek-R1-Distill-Qwen-1.5B），在 11 个 benchmark 上它只新增了 48 条可达的正确解，却丢掉 175 条（约 3.6:1）；Nemotron-7B 和 Skywork-OR1-7B 是 2:1 到 3:1。Net Discovery Rate（新发现占比）在所有 benchmark 上不超过 0.04，数学上不超过 0.01。他们给出的最大 $k$ 测量是 AIME2024 上 base 的 **pass@8192 = 93.3%** vs ProRL-1.5B 的 83.3%——这是我在这场争论里见到的最大采样预算。

最有意思的是它反过来回答了"什么时候真的会扩张"，而两种情形都不是新推理：一是 RLVR 把 base model 长尾里已有的子技能重新组合起来（graph coloring 的局部移动、arc_1d 的逐元素更新、boxnet 的 JSON 片段——base 对单个片段有非零概率，只是拼不出全局正确解）；二是 RLVR 纠正了 prompt 格式错配，把本来就有、但被格式压制的能力释放出来。他们用困惑度佐证："这些'新'补全是已有推理模式的风格或格式变体，而非超出 support 的全新解。"

## 思考与讨论

**$\Delta_{\text{SE}}$ 这个指标的野心值得单独说。** 它把"RL 模型的 pass@1 追上 base 的 pass@256"设为目标。如果真能做到，等于用一次采样的成本拿到 256 次采样的覆盖率。目前差距在 40 个点以上，说明这里的空间比算法之间 1.3 个点的差异大两个数量级。作为一个研究方向的标尺，这比"在 AIME 上再涨两个点"有意义得多。

**MATH500 上的反例值得追，而且有人把它变成了一个 benchmark。** 六种算法在 MATH500 的 pass@256 全部略高于 base，这与主结论相反。我倾向于认为这是饱和效应（base 已经 96.2%）。MATH-Beyond（[arXiv 2510.11653](https://arxiv.org/abs/2510.11653)，图宾根/MPI）把这个观察推到底：正因为 base model 在 MATH-500/AIME24 上 pass@1024 已接近饱和，"现有形式的测试集从根本上不足以衡量——也不足以激励——真正的进步"。他们构造了一个 base pass@1024 ≈ 0 的题集，然后测各模型的"扩张率"：DeepScaleR-1.5B 5.22%、Nemotron-Research-Reasoning-Qwen-1.5B v1 7.83%/v2 9.57%、Skywork-OR1-7B 21.21%，而长 CoT **蒸馏**的 Qwen3-4B 是 58.93%、Qwen3-8B 66.38%。这既独立复现了本文"蒸馏比 RL 更能扩边界"的结论，也说明"RL 扩不动"这句话有多少是 benchmark 顶到天花板的产物。

顺着这条线，On the Interplay of Pre-Training, Mid-Training, and RL（[arXiv 2512.07783](https://arxiv.org/abs/2512.07783)）做了一个完全可控的版本：100M 参数模型从零在 10B token 的合成算术题上预训练，再做 GRPO。在 pass@128 已接近饱和的同分布任务上，pass@1 明显提升而"pass@128 无论用什么 RL 数据都没有改善"——本文的交叉签名被复现了，并被解释为预训练饱和；而当 RL 数据落在"能力边缘"的难度带时，OOD 上的 pass@128 最高提升 42%。这把"边界收窄"重新定位成了一个关于 benchmark 剩余空间的陈述，而不是关于 RL 的陈述。

**KL 项那个结果值得一个解释。** 加 KL 后 pass@1 不变但 pass@128 更低，这与"KL 约束模型不要偏离 base"的直觉相反。如果 KL 真的把策略拉向 base，pass@k 应该更接近 base 才对。可能的原因是 KL 惩罚在抑制长尾 token 上的作用比在抑制分布整体偏移上更强，但论文只给了一句观察，没有分析。

**分歧其实比看起来小。** 把 ProRL 的三类划分和这篇论文的结果叠在一起看，双方在"数学上 RL 扩不动边界"这点是一致的，争的是代码、逻辑谜题、STEM 这些领域算不算数。这个共识本身指向一个更有用的问题：为什么偏偏是数学？两个候选答案——数学是被预训练反复训过的领域（所以 base 的 pass@k 已经接近饱和），以及数学 benchmark 的污染最严重——都指向 base model 那一侧，而不是 RL 算法那一侧。Invisible Leash 的 NDR 数据给这个划分提供了独立支持：非数学数据集的新发现率最高（≤0.04），数学几乎停滞（≤0.01）。

**"扩张"这个词需要拆开。** Invisible Leash 观察到的两种真实扩张——重组 base 长尾里的子技能、纠正格式错配——都不是这篇论文所否认的那种"新推理模式"，但也确实不是纯粹的采样效率提升。这提示"边界"其实是个三层结构：base 概率严格为零的解（策略梯度碰不到，有定理保证）、概率极低但非零的解（RLVR 可以捞上来，这是真实增益）、以及已经有相当概率的解（RLVR 只是加权）。这篇论文的 pass@k 实验把后两层混在一起测，所以既低估了 RLVR 在第二层的作用，也没能区分第一层的硬约束。

## AI 犀利评判

下面分十二个方向。一到三质疑"base model 的 pass@k 是否真的在度量推理"这个前提；四到六关于超参、模板与代表性，指向结论的适用范围；七到九关于指标的定义与有效性；十到十二关于证据强度和解释本身的稳定性。

### 一、base model 的大 $k$ 优势里，有多少是记忆

这是我认为最伤的一点，而且它已经不是猜测。

主结论建立在 Qwen2.5 系列的 base model 在 $k$ 大时能解出 RL 模型解不出的题。但 Qwen2.5 在数学 benchmark 上的污染有直接证据。[arXiv 2507.10532](https://arxiv.org/abs/2507.10532)（AAAI 2026）做了一个补全实验：把题目截断到前 40%/60%/80% 喂给模型，看它能不能把剩下的部分原样续写出来（ROUGE-L / 精确匹配，%）：

| 模型 | 数据集 | 80% 前缀 | 60% 前缀 | 40% 前缀 |
|------|--------|---------|---------|---------|
| Qwen2.5-Math-7B | MATH-500 | 81.3 / 65.8 | 78.1 / **54.6** | 69.0 / **39.2** |
| Qwen2.5-7B | MATH-500 | 66.4 / 40.2 | 61.0 / 21.2 | 50.4 / 8.2 |
| LLaMA3.1-8B | MATH-500 | 48.3 / 17.8 | 40.6 / **3.8** | 32.1 / **0.6** |
| Qwen2.5-Math-7B | AIME2024 | 74.0 / 56.7 | 55.3 / 20.0 | 57.7 / 16.7 |
| Qwen2.5-Math-7B | AIME2025 | 54.7 / 16.7 | 34.9 / **0.0** | 27.4 / **0.0** |

只给 40% 的题面，Qwen2.5-Math-7B 能把 MATH-500 剩下 60% 精确复现的比例是 39.2%，LLaMA3.1-8B 是 0.6%。而 AIME2025（发布于 base model 训练截止之后）上，Qwen 的精确匹配掉到 0.0%——这是这组实验最重要的对照：效应随 benchmark 的**发布时间**变化，不随模型的**数学能力**变化（MinervaMath 和 LiveMathBench 上所有模型都趋于 0，包括 Qwen）。同一篇还有一个更直接的数字：只给部分题面让模型直接作答，Qwen2.5-Math-7B 在 AIME2024 上的准确率在 100%/80%/60%/40% 四种截断下**完全不变**（都是 13.33%），AMC 上 100% 与 80% 相同（53.01%）、60% 与 40% 也相同（43.37%）；同一列 LLaMA3.1-8B 在 MATH-500 上是 1.60/2.00/2.40/2.00，即完全不会做。题面少掉一半而答对率不动，这个模式与"解题"不符，与"检索"相符。代码上更极端：LiveCodeBench 题面给 40%，Qwen2.5-7B 的精确复现率是 70.9%，LLaMA3.1-8B 是 0.0%。

更干净的一个实验来自 VAR-MATH（[arXiv 2507.12885](https://arxiv.org/abs/2507.12885)，香港理工大学）：把 AMC23/AIME24/AIME25 的题目符号化，同一道题换一组数值生成多个变体，要求全部答对才算通过。如果模型是真在解题，换数值不该有影响。结果（strict 判据下的降幅）：

| 模型 | AMC23 | VAR-AMC23 | 降幅 | AIME25 | VAR-AIME25 | 降幅 |
|------|-------|-----------|------|--------|------------|------|
| Qwen2.5-MATH-7B | 36.9 | 2.0 | **−94.5%** | 4.8 | 0.0 | **−100%** |
| Qwen2.5-32B | 33.4 | 3.1 | **−90.6%** | 3.5 | 0.0 | **−100%** |
| Oat-Zero-7B | 65.6 | 36.8 | −43.9% | 9.2 | 1.2 | −87.4% |
| SimpleRL-Zoo-7B | 61.4 | 33.6 | −45.3% | 12.5 | 2.9 | −76.9% |
| DeepSeek-R1-0528 | 100.0 | 96.4 | −3.6% | 81.5 | 61.3 | −24.8% |
| OpenAI-o4-mini-high | 100.0 | 93.4 | −6.6% | 93.4 | 76.7 | −17.8% |

前两行正是这篇论文的两个主力 base model。换个数值，Qwen2.5-MATH-7B 在 AMC23 上从 36.9 掉到 2.0，而 R1-0528 只掉 3.6%。这直接冲击"base model 在大 $k$ 下解出的题体现了推理能力"这个前提——至少有一大块是对具体数值模板的记忆。顺带一提，被评测的 Oat-Zero-7B 和 SimpleRL-Zoo-7B 降幅也很大（−43.9%/−45.3%），说明这个问题是 base 和 RL 模型共有的，但 base 的绝对降幅更极端。

而污染会以**恰好符合论文预测的方式**表现出来：一道背下来的题在 base 分布里是一条低概率但存在的回忆路径，$k=1024$ 时被采到；RL 训练把概率质量集中到"按格式推理"上，反而压掉了这条回忆路径。这与"能力边界收窄"在 pass@k 曲线上完全同形，而论文的实验设计无法区分二者。

### 二、Qwen 上的 RL 收益，随机奖励也能拿到大半

另一条旁证是 Spurious Rewards（[arXiv 2506.10947](https://arxiv.org/abs/2506.10947)，Rulin Shao、Stella Li、Nathan Lambert、Luke Zettlemoyer 等，UW / AI2 / UC Berkeley）。在 Qwen2.5-Math-7B（MATH-500 基线 49.4）上跑 300 步 GRPO：

| 奖励信号 | MATH-500 涨幅 |
|---------|-------------|
| 真实答案 | +29.1 |
| 多数投票 | +27.1 |
| **错误标签** | **+24.1** |
| **随机（50% 概率给 1）** | **+21.4** |
| 仅格式（有 `\boxed{}` 就给分） | +13.8 |

随机奖励拿到了真实奖励七成以上的收益，错误标签拿到八成。而同样的处理换到非 Qwen 模型上就失效：LLaMA3.1-8B-Instruct（基线 36.8）只有真实奖励 +7.4、多数投票 +7.2 为正，其余四种奖励全部为负（−1.3 到 −11.5）；OLMo2-7B（基线 9.0）只有真实奖励 +15.5 明显有效，spurious 奖励在 −2.1 到 −8.3 之间。论文的原话是"OLMo 在 spurious 奖励下持平，主要靠真实奖励才有收益"。

他们自己的解释不是污染而是"GRPO 的 clip 项系统性地放大 base model 里先验概率高的 token"：Qwen2.5-Math-7B 的 code reasoning（用 Python 写推理但从不执行）频率是 65.0%，RLVR 后 15 步内升到约 90%，随机奖励下最高 95.6%。这个行为对 Qwen2.5-Math 确实有用（带代码的回答准确率 60.9%，纯自然语言 35.0%），而 Qwen2.5-1.5B、OLMo2-7B、LLaMA3.1-8B-Instruct、LLaMA3.2-3B-Instruct "从不生成代码"，所以 clip 偏置没有可放大的东西。值得注意的是这个机制并非普遍有利：Qwen2.5-7B 的 code 频率本来就有 92.2%，但它带代码时准确率反而更低（39.9% vs 61.5%）。

他们也报告了一个与污染假设一致的对照：Qwen 上靠 spurious reward 拿到的 AIME24 收益（format +10.3、incorrect +10.2、random +10.2，对比真实奖励 +15.3），换到 AIME25（所有被测模型的知识截止之后）后只剩 −0.4 到 +4.5。

（一个细节：这篇论文正文里"AMC 上也观察到类似趋势，format/incorrect/random 分别涨 13.8%、24.1%、21.4%"这句话，三个数字与 MATH-500 的数字逐一相同，而 AMC 结果只以曲线图形式出现在附录 C。这看起来是复制粘贴的笔误，所以 AMC 的具体数值不宜引用。）

无论叫污染还是叫行为放大，共同的结论是：Qwen2.5 在数学 benchmark 上的表现里有一块不是推理，而这块恰好是这篇论文用来定义"能力边界"的那块。

### 三、作者的两道防线，方向是反的

针对上面两节的质疑，论文其实设了两道防线，但都不够。人工检查 CoT 只能排除"答案对但推理错"，不能排除"推理链本身是背下来的题解"——一条从记忆里复现的正确解法，人工看上去与真实推理无法区分。"过滤可猜题"的规则是"不用 CoT 直接答、能以 <5% 概率答对就剔除"，它筛掉的是**随机撞对**；而记忆表现为高置信度地直接答对，按论文的规则这类题被**保留**（原文明确说"能以高概率直接答对的题目予以保留，因为它们较简单且可用有效 CoT 解出"）。也就是说这个过滤器的方向，对记忆污染这个假设是反的。

真正能切开这个问题的实验，论文其实做了一半却没有解读。它有 LLaMA-3.1-8B，而那一列（Figure 2 最右）恰恰是全文最弱的证据：AIME24 上两条线基本重叠在 0.3 以下、看不出交叉，MATH500/Olympiad 上交叉发生得很晚。如果污染是主要驱动，正应该看到"Qwen 上现象强、LLaMA 上现象弱"——这就是图里的样子，而论文没有讨论这个跨模型族的差异。需要说清楚的是 LLaMA-3.1-8B 是全文**唯一**的非 Qwen 血统 base model（后来加的 Mistral-Medium-3 只有 API），所以"跨模型族验证"这个说法在实际覆盖上只有一个样本。另一个干净做法是用发布日期晚于训练截止的题目，论文只在 Magistral 那组用了 AIME25，而那组恰好没有出现交叉。CoT-Pass@K 那篇（[arXiv 2506.14245](https://arxiv.org/abs/2506.14245)）给出了正面证据：换成"答案与推理链都要对"的指标后，交叉在 AIME24/AIME25 上消失，且 AIME2025 上差距最大——与污染假设的预测一致。

顺便说，v5 全文里 "memoriz"、"leak"、"verbatim" 出现 0 次，"contamin" 只出现一次（在一条参考文献标题里）。这不是疏忽——上述几篇质疑都发表在 v1 之后，而论文改到 v5（2025 年 11 月）时并未把它们纳入讨论。

### 四、T=0.6 是一个对 base model 有利的选择

而这一点被论文自己的图证明了。Figure 17 显示 base model 的 pass@k 对温度极其敏感（MATH500 上 $k=1$ 从 T=0.6 的 0.62 掉到 T=1.2 的 0.29；AIME24 上从 0.08 掉到 0.02），RL 模型几乎不动。T=1.2 时 base 在两个数据集上已经全程被 RL 压制——也就是说主结论的方向可以被一个采样超参翻转。作者据此选 0.6，理由是"让两个模型都发挥最佳"。但"最佳"按什么定义？如果按 pass@1，0.6 对 base 有利；如果按大 $k$ 的 pass@k，多样性更重要，两个模型的最优温度都可能不是 0.6。最公平的对照是"各自搜索最优温度、在各自最优点比较"，论文没有做。它只做了单向的熵匹配（把 RL 升温到 base 的熵），没有做另一个方向。

top-p=0.95 全程固定这点更少被提到。对一个熵已经坍缩的 RL 模型，nucleus 截断的实际影响很小；对一个熵很高的 base model，0.95 恰好保留了长尾里的多样性，而这正是它在大 $k$ 上取胜的来源。温度和 top-p 构成一个二维空间，论文只沿温度扫了三个点，且熵匹配实验里只对 RL 模型动手。

这类超参敏感性有一个独立的量级参考。A Sober Look at Progress in Language Model Reasoning（[arXiv 2504.07086](https://arxiv.org/abs/2504.07086)）报告在这类小规模数学 benchmark 上，pass@1 的跨种子标准差是 5–15 个百分点，AIME'24 上一道题就值 2.5–3.3 个点，温度带来的波动可达 15%、top-p 8%、甚至硬件/集群差异 6–8%。而 Figure 2 里多处交叉点附近两条曲线的间距就在几个百分点量级。

### 五、prompt 模板这一层的影响，被评测对象自己的作者量化过了

论文明确说不给 base model few-shot，用与 RL 训练相同的 zero-shot prompt，并承认 base model "在没有 few-shot 引导时经常输出格式混乱甚至无意义的内容"。而 Understanding R1-Zero-Like Training（[arXiv 2503.20783](https://arxiv.org/abs/2503.20783)，Sea AI Lab——正是本文评测的 Oat-Zero 的作者）测过模板的代价，Qwen2.5-Math-7B 在五个数学 benchmark 上的平均分：

| 模板设置 | AIME24 | MATH500 | 五项平均 |
|---------|--------|---------|---------|
| 4-shot prompting | 3.3 | 61.6 | 23.8 |
| R1 模板 | 0.0 | **0.0** | **0.0** |
| Qwen 模板 | 16.7 | 50.6 | 26.5 |
| 不用模板 | 0.2 | **69.0** | **38.2** |

R1 模板让这个 base model 在每个 benchmark 上归零。他们的解释是 Qwen2.5-Math 可能直接在拼接的问答文本上预训练过，所以"不加模板时 base 模型本来就已经像做过 SFT 一样"，结论是"套模板实际上是先破坏了能力，再由 RL 把它重建回来——这意味着我们对纯 RL 带来的巨大收益应当更保守"。

这个发现对本文是双向的。一方面它说明论文测到的 base 曲线可能是**低估**，交叉点因此是保守的（对论文有利）；另一方面它说明交叉发生在哪个 $k$ 是模板的函数，而不是模型的固有性质。而论文正是用交叉点的存在与位置来论证"边界收窄"。

至于训练侧：RL 训练用 T=1.0、每 prompt 8 个 rollout。论文自己的消融显示 $n$ 从 8 增到 32 会提升大 $k$ 的 pass@k（Figure 16），也就是"探索不足"这个因素被实验证实存在方向性影响，但因为算力限制只训了 220 步、未收敛，作者把这个问题留给了未来工作。用一组已知探索不足的超参训出的模型，去论证"RL 无法探索出新路径"，逻辑上是把待证结论放进了前提。ProRL 正是往这个方向加码：rollout 温度 1.2、$n=16$、DAPO 的非对称 clip（$\epsilon_{\text{low}}=0.2$、$\epsilon_{\text{high}}=0.4$）加动态采样、KL 控制配参考策略重置、训 2000 步以上——然后报告了 base 完全不具备而 RL 模型能解的任务。值得注意的是 ProRL 自己也说清了单靠升温不够："提高 rollout 温度只是延迟熵坍缩的到来，而非阻止它"。这恰好说明这篇论文的熵匹配实验（只在推理时给 RL 模型升温）处理的是症状而非成因。

### 六、"RLVR"被 SimpleRLZoo 代表了

主实验的 RL 模型来自在 GSM8K + MATH 训练集上跑几百步 GRPO 的开源复现。这是 2025 年 4 月能拿到的东西，不是 RLVR 这个方法的上限。摘要写的是 "current RLVR"，但标题问的是 "Reinforcement Learning"，正文的机制解释（先验双刃论）也是关于 RL 这个范式的一般论断。这个跨度在传播中被简化成了"RL 不能超越 base model"。ProRL 的 boxnet 结果（base 完全不具备该能力，训 2000 步后能解）不推翻论文在其实验范围内的观察，但推翻了那个被广泛传播的一般化版本。

而且要看清双方共识在哪：ProRL 用完全相同的采样参数（T=0.6、top-p 0.95），在数学上复现了 pass@128 下降。真正的分歧不是"RL 能不能扩边界"，而是"在哪些领域能"。论文的主战场（数学）恰好是双方都同意 RL 扩不动的那个领域——而数学也正是污染最严重、base model 被预训练反复训过的领域。这两件事同时成立时，"RL 扩不动"和"base 的 pass@k 虚高"就成了同一个现象的两种读法。

### 七、pass@256 作为"能力边界"，作者自己承认这个锚点没有饱和

论文承认 $k$ 足够大时随机采样也能撞对，然后用"$k=128$/1024 在现实算力内"收尾。但算力可行性不等于指标有效性。$k=256$ 的 base model 用了 256 倍的推理算力，把它的 pass@256 叫做"能力上界"、把 RL 模型的 pass@1 叫做"当前水平"、宣布二者之差是 RL 的失败——这个比较从一开始就不是 compute-matched。

更要紧的是，在 GitHub issue #1 里有人直接问"你们很多曲线在 pass@256 处还没到渐近线，不是应该一直加大 $k$ 到曲线走平吗"，第一作者的回答是："是的，你完全正确，很多曲线在 pass@256 处确实还没完全走平。我们用 $k=256$ 主要是因为**这是我们算力预算下的合理折中**，加大 $k$ 当然能给出更完整的推理边界图景。"如果 base 曲线尚未饱和，那 $\Delta_{\text{SE}}$ 就不是模型的性质，而是算力预算的函数——换个预算，这个"上界"和这个"差距"都会变。

### 八、真正的 compute-matched 实验后来有人做了，结论对 RLVR 更不利

Reasoning with Sampling（[arXiv 2510.14901](https://arxiv.org/abs/2510.14901)，Aayush Karan、Yilun Du，Harvard）不做任何训练、不用验证器、不用数据，只在 base model 上跑一种 MCMC power sampling：

| Qwen2.5-Math-7B | MATH500 | HumanEval | GPQA |
|-----------------|---------|-----------|------|
| Base | 0.496 | 0.329 | 0.278 |
| Power Sampling | 0.748 | 0.573 | 0.389 |
| GRPO (MATH) | 0.785 | 0.537 | 0.399 |

而且算力账算得很明确：power sampling 的 token 开销是标准推理的 **8.84 倍**，"大致相当于一个 epoch 的 GRPO 训练成本（按每样本 8 个 rollout 估），而通常一个 GRPO epoch 还更贵，因为它用 16 个 rollout 且训练集比 MATH500 大"。pass@k 上他们的说法是："与 GRPO 在大 $k$ 处走平不同，power sampling 在 $k>1$ 时显著更优，而且我们的曲线一路超过 base model，最终才收敛。"

这组结果同时支持和削弱了本文。支持的部分：base model 里确实藏着 GRPO 级别的单次性能，RLVR 没有教会它新东西。削弱的部分：如果换一种采样方式就能在**可比算力**下拿到 RL 的 pass@1 而不牺牲 pass@k，那"$\Delta_{\text{SE}}$ 有 40 个点的空间"这个叙事的主角就不该是新的 RL 算法，而是推理时的搜索。

### 九、"答案对"和"推理对"的缺口比论文估计的大

论文的 CoT 人工检查只覆盖 GSM8K（25 道）、AIME24（7 道）和视觉推理（8 道）——MATH500、AMC23、Minerva、Olympiad 这四个 benchmark 上一条 CoT 都没查，而它们是 Figure 2 里 12 个 Qwen 子图的三分之二。而且它引为方法先例的 Large Language Monkeys（arXiv 2407.21787）自己的审查规模也只有 105 条 CoT、单一模型、单一数据集。

后续工作把这个缺口量化了。Curing "Miracle Steps"（[arXiv 2510.07774](https://arxiv.org/abs/2510.07774)，ACL 2026）在 AIME2024 上比较 Pass@1024 与"推理链也要成立"的 Verified Pass@1024，两者差 **31.2 个百分点**（Verified 只有 26.7%）。他们还做了一个直指记忆的探测：完全不给 CoT、只让模型直接输出答案，正确答案出现在 Top-64 beam 候选里的比例是 33%–73%，而在那些"靠 miracle step 蒙对"的题上高达 83%（其他类型假阳性是 63%）。值得注意的是这篇论文明确反对"AIME 答案是 0–999 所以容易蒙"这个解释（候选答案并不聚集在小整数上，而是分布在与具体题目相关的数值范围），他们归因于记忆——这比"随机猜"对本文的主结论更不利，因为随机猜可以用大样本平均掉，记忆不能。

CoT-Pass@K 那篇给的数字方向一致：DAPO 训练 400 步后，在已经完全优化的训练题目上，"答案正确"的 rollout 里中位约 30% 携带无效推理。这是 RL 模型在训练集上的数字，base model 在困难 benchmark 上只会更高。论文用"$k=1024$ 里至少存在一条正确 CoT"这个宽松判据来支撑 pass@k 的可靠性，但 pass@k 本身统计的也是"至少一次对"——两个都取 max 的判据叠在一起，对假阳性的容忍度比看起来高得多。

### 十、关于蒸馏的对比，方向是对的，但控制变量没做

Figure 7 里 Distill 全程高于 Base，被用来论证"蒸馏能扩展边界、RL 不能"。但 DeepSeek-R1-Distill-Qwen-7B 见过的 token 数量、以及那些 token 的信息密度（来自 R1 的长 CoT），和 Oat-Zero 的 RL 训练量完全不可比。这个对比证明的是"从更强的教师那里学能变强"，这一点没人怀疑；它不能单独支撑"RL 这个算法家族有结构性缺陷"。要做这个论证，需要在匹配的数据量/算力下比较，或者做论文自己在 Discussion 里提到的那个实验——从蒸馏后的模型出发再做 RL，看边界能否继续外扩。论文提了这个想法，但没做。（CoT-Pass@K 那篇顺手给了一个负面数据点：对已蒸馏模型做 RLVR，在数学上即使用 CoT-Pass@K 也看不到大 $k$ 的差距。）

### 十一、误差棒的缺失格外要紧，而且已经有人复现不出来了

AIME24 只有 30 道题。Table 2 里"0.0% 的题是 RL 会而 base 不会"，分母是 30；"13.3%"是 4 道题。MATH500 上的"1%"是约 5 道题。这些数字被用来支撑"近似子集关系"这个相当强的结构性论断，但全文没有跨种子的重复实验，没有 bootstrap 置信区间。pass@k 的估计量本身是低方差的（相对于朴素估计），但这只降低了给定 $n$ 个样本时的估计方差，不解决 30 道题带来的题目层面抽样方差。

论文自己的 GitHub 上有两个独立的复现报告，都指向交叉点的脆弱性。Issue #10（2025-07，已关闭）：有人在 Minerva 上跑 Qwen2.5-7B vs Qwen2.5-7B-SimpleRL-Zoo，"RL 模型直到 $k=128$ 都持续领先 base，而论文里从 $k=32$ 左右就开始落后"。他随后用 README 里的脚本、$n=32$ 复现出了论文的图，自己也困惑："这对我来说很奇怪，因为我用的应该是同一组生成超参。"作者以"结果可以复现"为由关闭了 issue，一个月后另一位用户追问"你找到造成这个差异的原因了吗"，无人回复。Issue #12（2026-06，**仍开放**）："base 和 RL 模型在论文指定的 $k$ 上并不交叉……这个问题只出现在 SimpleRL Zero 模型上，OatZero 模型的表现与论文一致。"作者的回复是"如果超参设置正确，可能是方差问题……可以跑更大的 $k$ 比如 256/512 来降低 pass@k 估计的方差"。

把这个回复和上面 5–15 个百分点的跨种子方差放在一起看，"这是方差"是一把双刃剑：如果交叉点位置受方差支配到需要加大 $k$ 才能稳定显现，那么"边界收窄了多少"这个量本身就需要误差棒才能读——而论文一个都没给。

### 十二、因果解释在版本之间换过一次

v1 的贡献列表把边界收窄直接归因于"RL 降低输出熵、限制探索"，Figure 18 的熵匹配对照当时不存在。加上对照后，结论改成"熵有贡献但不足以完全解释"，而"不足以完全解释"的部分就转由"先验双刃论"来承担。这个新解释目前没有独立的实验支撑——它是一个对残差的说明，而不是一个被检验的假设。论文列出的四个未来方向（高层抽象探索、课程数据、过程奖励、agentic RL）都是从这个未被检验的解释推出来的。

### 一句话判断

这篇论文最扎实的贡献是把评测指标从 pass@1 换到大 $k$ 的 pass@k，并做了跨三个领域、六种算法的系统测量，"RLVR 主要提升采样效率、且六种算法与 base 潜力的差距远大于彼此差距"这个观察在其实验范围内可靠；但"边界收窄"这个更强也被引用最多的结论，同时暴露在 Qwen2.5 数据污染（换个数值 base 掉 90% 以上）和采样超参选择（自己的 Figure 17 显示 T=1.2 就能翻转方向）这两个未被控制的混淆因素之下，而论文自己的 LLaMA-3.1 结果和 Magistral 结果恰恰是这两个方向上最不支持它的两组数据。
