这四篇论文可以连起来读成一条逐步扩展的路线：**如果训练时有一些推理或评价信息，怎样让模型在推理时看不到这些信息，却仍然学会其中的行为？** OPSD 先把正确答案作为 privileged information（PI）用于数学推理；RuPI 将 PI 换成适合开放式任务的 rubric；RCSD 进一步学习如何自动生成 rubric；PaperGym 则把 rubric、数据构造和 RL 训练组织成研究计划环境。

## 快速概览

传统 SFT 在固定的专家轨迹上训练，容易遇到 exposure bias；GRPO 等 RL 方法让模型自己采样，却通常只有一个序列级的稀疏奖励，而且每个问题需要采样一组答案。OPSD 取了中间路线：模型自己生成轨迹，因此训练分布贴近推理分布；同一个模型再在额外上下文中充当 teacher，用每个 token 的完整概率分布提供密集监督。

第一篇的额外上下文是正确解，适用于答案可验证的数学任务。第二篇的额外上下文是 rubric，例如“应解释耳痛的可能原因”“不应在缺少用药信息时直接推荐耳药水”。Rubric 不指定唯一措辞，而是描述一组高质量回答共同满足的偏好。论文的核心经验是：在开放式任务上，rubric 对学生自己生成的轨迹提供的 KL 信号比单个 reference completion 更强、更对准训练分布。

## 共同框架：三种训练信号的差别

设问题为 $x$，参考答案为 $y^\star$，学生生成的轨迹为 $\hat y$。这里先把四篇论文共同面对的三种训练信号放在一起；它们的差别主要在训练数据和反馈粒度：

| 方法 | 训练轨迹 | 反馈 | 外部组件 | 结构性代价 |
|---|---|---|---|---|
| SFT / reference distillation | 固定参考轨迹 | 参考 token | 参考生成器 | 训练前后分布不一致 |
| GRPO / rubric-as-reward | 学生采样，通常每题 $G$ 条 | 每条轨迹一个标量 | verifier 或 LLM judge | 采样昂贵，奖励同质时梯度为零 |
| OPSD / RuPI | 学生自己的 on-policy 轨迹 | 每个位置的词表分布差异 | 同一个模型的 privileged context | 需要两次前向并保存词表 logits |

GRPO 的组内优势可写为

$$A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)}.$$

奖励 $r_i$ 只告诉我们第 $i$ 条完整答案是否好，并且同一条答案中的所有 token 共享 $A_i$。若 $G$ 条答案全对或全错，标准差为零，整个 group 没有更新信号。OPSD、RuPI 和 RCSD 都不需要组，也不要求最终答案已被判定正确；它们在学生实际走过的每个前缀上比较两个条件分布。PaperGym 在此基础上再加入一个完整的 GRPO 阶段，用 rubric 对整条研究计划做结果层面的校正。

## 论文一：正确答案作为 hard PI

### 从同一模型构造 teacher 和 student

给定数学数据集

$$\mathcal S=\{(x_i,y_i^\star)\}_{i=1}^{N},$$

学生只看到题目：

$$p_S(\cdot\mid x)=p_\theta(\cdot\mid x),$$

teacher 看到题目和参考解：

$$p_T(\cdot\mid x,y^\star)=p_\theta(\cdot\mid x,y^\star).$$

两者共享参数 $\theta$，区别只在上下文。学生先按自己的策略采样

$$\hat y\sim p_S(\cdot\mid x).$$

然后把同一段学生前缀分别送入两个上下文，在位置 $n$ 比较完整词表上的 next-token 分布。训练目标是

$$
\mathcal L_{\mathrm{OPSD}}(\theta)=
\mathbb E_{(x,y^\star)\sim\mathcal S}
\mathbb E_{\hat y\sim p_S(\cdot\mid x)}
\left[\frac{1}{|\hat y|}\sum_{n=1}^{|\hat y|}
D\!\left(p_T(\cdot\mid x,y^\star,\hat y_{<n})\,\middle\|\,p_S(\cdot\mid x,\hat y_{<n})\right)\right].
$$

这里 $D$ 可以是 forward KL、reverse KL 或 Jensen–Shannon divergence；反向传播只经过 student logits，teacher 的分布被当作条件化后的目标。直觉上，student 先暴露自己会走到的错误前缀，teacher 再在这些前缀上展示“看过正确解之后，下一步更应该怎样分配概率”。这保留了 on-policy 的状态覆盖，又把一个答案是否正确的粗反馈变成了每个位置、整个词表上的软反馈。

![OPSD 的 teacher–student 数据流](/assets/images/opsd-rupi/opsd.png)
*Figure 1：学生从只含问题的上下文采样；teacher 在额外参考解上下文中评估同一条学生轨迹。teacher 不另外生成一条训练答案，而是通过一次 prefilling / forward pass 产生条件分布。*

### 为什么不直接 SFT 正确解

SFT 只在固定的 $y^\star$ 前缀上训练。模型真正回答时会走到自己生成的前缀，因此某个早期小错误可能把后续上下文带到训练分布之外。OPSD 每轮都在学生当前访问的前缀上计算损失，形式上更接近 imitation learning 中“在 learner 访问的状态上请求指导”。

这并不意味着 OPSD 忽略了参考解。参考解仍然是 teacher 的 PI，只是它不再作为一条必须逐 token 复制的离散目标。论文的提示词让 teacher 在看过参考解之后“用自己的方式重新解题”，使参考解更像帮助 teacher 理解问题的证据，而不是 student 必须照抄的文本。

### 一个重要的稳定化：pointwise KL clipping

作者发现，不同 token 的 KL 贡献呈重尾分布，连接词、语气词等 style token 可能比数字、运算符和数学关键词产生更大的差异。如果直接相加，优化会偏向语言风格而不是数学推理。对每个位置 $n$ 和词表项 $v$，先计算

$$\ell_{n,v}^{(f)}=p_T(v\mid\cdot)f\!\left(\frac{p_S(v\mid\cdot)}{p_T(v\mid\cdot)}\right),$$

再使用

$$D_{\mathrm{clip}}^{(f)}=\frac{1}{|\hat y|}\sum_n\sum_{v\in\mathcal V}\min(\ell_{n,v}^{(f)},\tau).$$

$\tau$ 是单个词表项贡献的上限。它不是把整条序列的损失裁掉，而是先限制少数异常大的词表项，避免 style 信号压过内容信号。

### 数学实验：更少采样，更密反馈

实验使用 Qwen3-1.7B、4B、8B Instruct，在 OpenThoughts 数学推理数据上训练，测试 AIME24、AIME25 和 HMMT25。指标是从同一问题采样 12 次的 Avg@12 准确率。主要结果如下：

| 模型与方法 | AIME24 | AIME25 | HMMT25 | 平均 |
|---|---:|---:|---:|---:|
| Qwen3-8B Base | 75.8 | 65.6 | 43.9 | 61.8 |
| Qwen3-8B + SFT | 72.3 | 64.2 | 42.9 | 59.8 |
| Qwen3-8B + GRPO | 76.4 | 68.9 | 46.7 | 64.0 |
| Qwen3-8B + OPSD | **77.8** | **70.8** | 45.8 | **64.8** |
| Qwen3-4B + OPSD | 76.4 | 68.3 | 46.1 | 63.6 |
| Qwen3-1.7B + OPSD | **57.2** | **43.9** | **29.2** | **43.4** |

同一训练预算下，OPSD 的每题只采一条、最多 1024 token 的轨迹；GRPO 每题采 8 条、每条最多 16k token。图中的前三个面板显示，Qwen3-1.7B 上 OPSD 在 AIME24、AIME25、HMMT25 都随训练步数上升，100 步时约为 57.2、43.9、29.2；GRPO 曲线较早停滞。最右面板显示，在 100 步内，GRPO 超过半数 batch 的 reward standard deviation 变成 0，因而没有梯度。这个现象解释了“更多采样”为什么没有转化成更多学习。

![OPSD 与 GRPO 的 token efficiency](/assets/images/opsd-rupi/methods_tokens.png)
*Figure 2：前三个面板是三个数学 benchmark 的 Avg@12，横轴为更新步数；第四个面板按生成 token 数比较平均准确率；最右为 GRPO 的零奖励标准差 batch 比例。OPSD 在更少生成 token、约 100 步内达到更高或相当的准确率。*

### 消融实验告诉我们的事情

**Forward KL 最适合这组数学设置。** Qwen3-1.7B 在 AIME25 的 base 为 36.7，step 50 时 forward KL 达到 43.9，step 100 为 41.1；reverse KL 只有 37.5 / 35.0，JSD 为 36.9 / 39.0。因此后续主实验采用 $\mathrm{KL}(p_T\|p_S)$。这不是一个普遍定理，而是说明“让 student 覆盖 teacher 的分布”在该任务和提示格式下更有效。

**学生 TM-off、teacher TM-on 的不对称最好。** Qwen3 的 thinking mode 会改变生成格式。学生关闭 thinking mode、teacher 开启时，1.7B 的 style / math / other KL 分别为 0.85 / 0.14 / 0.25，数学 token 的信号高于其他组合；但 style 的 KL 也最高，所以更需要 pointwise clipping。论文把这种配置用于主实验。

**更长的学生轨迹没有稳定收益。** 将蒸馏生成长度从 1024 提高到 4096，并没有在 AIME24、AIME25 上一致提升。早期 token 更像推理分叉点；当前缀变长后，teacher 对后续 token 的预测更确定，新增位置的差异反而变小。

**完整词表蒸馏胜过 sampled-token 目标。** Qwen3-4B、2048 token 的实验中，full-vocabulary logit distillation 在 AIME25 / HMMT25 上为 84.1 / 60.0，sampled-token policy-gradient 版本为 82.1 / 57.3。代价是每个位置要保存词表大小的 logits，峰值显存更高。

## 论文二：从 hard PI 到 soft rubric PI

### 为什么 reference completion 在开放式任务上不理想

数学题常有一个可验证答案；医学咨询、长答案问答或创作任务通常存在许多都合格的回答。若把一条 reference completion 放进 teacher 上下文，teacher 很容易把概率质量集中在这一个文本上。student 在自己的轨迹上却很可能离这条文本很远，于是“teacher 看起来很确定”并不等于“student 的当前状态得到了有用指导”。

第二篇提出把 rubric 直接作为 teacher 的 system message。Rubric 包含“response should”和“response should NOT”两组自然语言标准，但不要求固定措辞。以 HealthBench 的耳痛问题为例，rubric 可能要求回答讨论感染、耳垢堆积和 swimmer’s ear 等原因，并要求在不了解药水具体成分前不要直接推荐使用；student 只看到用户问题。

其损失是 reverse KL 的逐 token 版本：

$$
\mathcal L(x,r,\hat y)=\frac{1}{|\hat y|}\sum_t
\min\!\left(\tau, D_{\mathrm{KL}}\left(\pi_{S,\theta}(\cdot\mid x,\hat y_{<t})\,\middle\|\,\pi_T(\cdot\mid x,r,\hat y_{<t})\right)\right).
$$

这里 $r$ 是 rubric，teacher 使用 student 的 EMA 参数（decay $\mu=0.02$）或冻结的 base teacher，student 没有 rubric。reverse KL 是 mode-seeking：学生优先吸收 teacher 的高密度行为，同时较少把所有 teacher 可能性都复制过来，因此作者认为它更有利于保持原有 instruction-following 能力。LoRA 配置为 rank 64、alpha 128，KL clip $\tau=5.0$。

### 先测“信号是否真的存在”

作者没有直接从最终分数倒推 rubric 有效，而是先在未训练的 Qwen2.5-7B-Instruct 上测学生 on-policy rollout 的 teacher–student KL：

| teacher 的 PI | Mean KL | Body KL（中间 80%） |
|---|---:|---:|
| Physician rubric | **0.373** | **0.326** |
| Reference completion | 0.212 | 0.189 |

rubric 的平均逐 token KL 是 reference 的约 1.7 倍。更关键的是，reference 的信号依赖评分在哪条回答上：在 student rollout 上 Body KL 只有 0.189，在 held-out gold completion 上却达到 1.666；rubric 在两者上分别为 0.326 和 0.313，几乎不变。这个对比支持一个机制解释：rubric 描述的是学生正在探索的“好回答集合”，reference 主要描述某个学生不一定会走到的单点。

另一个诊断是 teacher 的 token NLL。对 gold completion 与其他 rubric-satisfying responses 比较时，reference PI 让 gold 的每 token NLL 为 0.38、其他好回答为 1.56，概率质量明显集中在 gold；rubric PI 则为 2.32 和 1.62，反而没有把质量过度集中到 gold。按论文的计算，hard PI 对单个 gold 的过集中程度约是 soft PI 的 6.5 倍。

### HealthBench：RuPI 胜过 rubric-as-reward RL

HealthBench 有 5000 个真实健康对话，每题有医生编写的加权 rubric；论文按 2000/500/2500 划分训练、验证和测试。RuPI 每个 prompt 只采一条学生 rollout；RaR GRPO 每题采 8 条，并用 GPT-4.1 逐 criterion 判定，再聚合成标量奖励。RuPI 训练时不查询外部 judge。

测试集的代表性结果如下。分数是 rubric satisfaction，数值越高越好：

| Base | 方法 | Test |
|---|---|---:|
| Qwen2.5-7B | Base | 0.169 |
|  | RaR GRPO | 0.193 |
|  | 最佳 RuPI（LoRA，forward KL） | **0.215** |
|  | 最佳 reference-PI（LoRA，forward KL） | 0.172 |
| Qwen2.5-14B | Base | 0.269 |
|  | RaR GRPO | 0.268 |
|  | 最佳 RuPI（full FT，forward KL） | **0.347** |
|  | 最佳 reference-PI（full FT，forward KL） | 0.267 |
| Llama-3.1-8B | Base | 0.141 |
|  | RaR GRPO | 0.116 |
|  | 最佳 RuPI（full FT，reverse KL） | **0.213** |
|  | 最佳 reference-PI（LoRA，forward KL） | 0.124 |

RuPI 在三个 base 上都超过 GRPO，并且每个训练 prompt 的 on-policy generation 数量少 8 倍。绝对差距在 Llama 上最大：0.213 对 0.116，约 +0.10；Qwen2.5-7B 上则是 0.215 对 0.193，差距较小。固定 reverse KL recipe 比较 soft / hard PI，RuPI 相对 reference-PI 的增益为 +0.034 到 +0.079，方向与前面的 KL 诊断一致。

HealthBench Hard 也呈现相同顺序。cluster aggregate 在 Qwen 7B / 14B / Llama 8B 上，base、GRPO、reference-PI、RuPI 分别为 0.503/0.535/0.501/**0.542**，0.698/0.706/0.701/**0.778**，0.532/0.515/0.545/**0.625**。accuracy 轴在 Llama 8B 上尤其有区分度：base、GRPO、reference-PI 都是 0，RuPI 为 0.077。

### KL 方向和泛化之间的权衡

在 HealthBench 的同域分数上，forward 与 reverse KL 通常相差约 0.015 以内，forward 在 Qwen 的 rubric 变体上略占优。但 IFEval 暴露了一个代价：Qwen 7B 的 forward-KL rubric LoRA / full FT 相对 base 分别下降 0.046 / 0.038，Qwen 14B 分别下降 0.041 / 0.034；reverse-KL rubric LoRA 在 Qwen 7B 反而是 +0.021。Llama 上两种方向变化较小。MMLU、GSM8K、TruthfulQA 没有明显系统性退化。因此论文建议：同域追求分数时两种 KL 都可用，若重视保持 instruction following，reverse KL 更稳妥。

### on-policy 是方法的一半

Qwen2.5-7B 的 rollout-source 消融直接改变了机制：rubric PI 的 on-policy 分数为 0.215，off-policy 为 0.154；reference PI 则是 0.172 与 0.156。按固定 LoRA、forward KL 的 $\lambda=0,0.5,1$ 混合实验，rubric 结果从 0.154 经过 0.167 上升到 0.215。off-policy 时 rubric 和 reference 几乎没有差别，且都不超过 base 0.169。换句话说，rubric 的优势不是把 rubric 文本塞进 teacher 就自动出现，而是“rubric 条件化 + teacher 在学生自己的状态上打分”共同产生的。

### 第二个领域：RubricHub Science → ResearchQA

作者把 HealthBench 之外的 Science split 作为训练域：从 RubricHub 与 rejection-sampling SFT 数据的 query 交集取 1000 个 prompt，每个 prompt 同时有 rubric、best-of-six reference 和可用于 GRPO 的 criterion reward；测试使用 ResearchQA 的 3750 个问题，指标是 rubric criterion coverage。

| 方法 | ResearchQA Test |
|---|---:|
| Qwen2.5-7B Base | 0.574 |
| RaR GRPO | 0.576 |
| Reference-PI（full FT，forward KL） | 0.642 |
| RuPI（LoRA，forward KL） | 0.660 |
| **RuPI（full FT，forward KL）** | **0.666** |

相对 base，最佳 RuPI 提升 0.092；相对 GRPO 提升 0.090。RuPI 在每个匹配 recipe 下都超过 reference-PI，说明这一结论至少不只依赖医学问答，但它仍然主要覆盖“有 rubric 的开放式问答”这一类任务。

## 论文三与论文四：从使用 rubric 到学习 rubric、构造环境

前两篇回答的是：**给定高质量 PI，rubric 是否比一条 reference completion 更适合作为 teacher 的上下文？** 后两篇分别把问题向前推进到 rubric 自动生成，向后推进到数据构造与训练环境：

| 论文 | 主要问题 | PI / 训练信号 | 与前文的关系 |
|---|---|---|---|
| [Rethinking Reward Supervision: Rubric-Conditioned Self-Distillation](https://arxiv.org/abs/2606.19327) | rubric 本身昂贵，怎样自动得到？ | Stage I 学 rubric generator；Stage II 用生成 rubric 做 forward-KL 蒸馏 | 把 RuPI 的“已有 rubric”变成“模型先学会生成 rubric” |
| [PaperGym: Rubric-Centered Evolution for Research-Plan Generation](https://arxiv.org/abs/2608.31119) | 怎样从科学论文批量构造可训练的研究计划环境？ | 论文结构化数据构造 + rubric-conditioned OPSD，再接 rubric-as-reward GRPO | 把 RuPI 从单纯蒸馏方法扩展成数据集、benchmark 和两阶段 RL pipeline |

### RCSD：Rubric 的生成也可以自蒸馏

第三篇论文将方法命名为 **Rubric-Conditioned Self-Distillation（RCSD）**。它和前文 RuPI 的直接区别是：RuPI 假设每个问题已经有医生或专家写好的 rubric；RCSD 把训练拆成两个模型角色和两个阶段。

**Stage I 学 rubric generator。** rubric generator 的 student 只看问题 $x$，teacher 同时看问题和参考答案 $y^\star$：

$$p_S^R(r\mid x),\qquad p_T^R(r\mid x,y^\star).$$

student 在自己的 rubric rollout 上匹配 teacher 的逐 token 分布。参考答案在这里不是让 student 复制的目标，而是 teacher 用来推断“一个好回答应该满足什么条件”的 privileged context。训练完成后，推理时只输入 $x$，generator 就能产生问题相关的 rubric。

**Stage II 训练 reasoner。** generator 先为问题生成 rubric $\hat r$；reasoner student 只看 $x$，reasoner teacher 看 $x,\hat r$。再对 student 的答案 rollout $\hat y$ 做 forward KL：

$$\mathcal L_{\mathrm{reason}}=\mathbb E_{\hat y\sim p_S^Y(\cdot\mid x)}\left[\sum_t D_{\mathrm{KL}}\left(p_T^Y(\cdot\mid x,\hat r,\hat y_{<t})\,\middle\|\,p_S^Y(\cdot\mid x,\hat y_{<t})\right)\right].$$

因此，RCSD 和 RuPI 都是“rubric → teacher 分布 → student on-policy token guidance”，但 RCSD 多了一个**把参考答案转化为 rubric 的 amortization 层**。它还使用约 10k rubric-generation 样本和 30k reasoning 样本，在 GPQA-D、SciBench、PIQA、RaR、ResearchQA、RubricHub 上评估；RuPI 则主要在 HealthBench / ResearchQA 上验证 rubric 作为 PI 的价值。

RCSD 的实验结果只简要记三点：Qwen3-8B 的六项平均分为 70.6，高于 OPSD 的 69.7、GRPO 的 69.2 和 SFT 的 65.4；ResearchQA 为 73.1，RubricHub 为 55.7。Forward KL 的平均分 70.6，高于 reverse KL 的 69.9 和 JSD 的 69.6。医学迁移上，MedMCQA / PubMedQA 从 base 的 64.5 / 74.2 变为 65.8 / 75.1。生成 rubric 与 reference rubric 的差距较小，例如 GPQA-D 为 64.5 对 65.2，说明 Stage I 并没有完全复刻人工 rubric，但保留了大部分训练价值。

这里与第二篇 RuPI 的 KL 结论有一个值得单独标出的差异：RuPI 在 Qwen / HealthBench 上发现 reverse KL 对 IFEval 保持更稳，因此推荐它用于能力保持；RCSD 在自己的 science reasoning 设置中发现 forward KL 总平均更高，并将其解释为覆盖更多 criterion-aware reasoning paths。两者并不矛盾，它们说明 KL 方向同时受任务、数据、模型和“追求多样性还是保持原行为”的目标影响。

### PaperGym：把 rubric 放进完整的研究计划训练环境

PaperGym 的中心贡献不再只是一个蒸馏 loss，而是**如何从论文生成可靠的任务—标准—评估器三元组**。它把每篇 arXiv 论文分成四类信息：Research Goal、Background、Research Method、Experimental Design，然后强制把：

- research question 从 Goal + Background 生成；
- reference answer 从 Method + Experimental Design 生成；
- specialized rubric 同时覆盖 methodological innovation 和 experimental design；
- general rubric 约束 completeness、specificity、soundness、efficiency、ethical safety。

这样做的目的，是避免问题本身泄露评分标准。已有 research-plan 数据集中，11.90%–34.10% 的 criteria 可以仅从问题推断；PaperGym-20k 把 criterion leakage 降到 3.73%，并包含 20,000 个来自 computer science、physics、economics 的实例。每个实例保留 10 个 atomic binary criteria，其中 63.8% 针对 method，36.2% 针对 experiment。

训练也比前文更完整：第一阶段使用 rubric-conditioned OPSD，让模型形成覆盖多个有效研究计划的 broad prior；第二阶段使用 rubric-as-reward GRPO，把 specialized rubric 与 general rubric 按 $0.7/0.3$ 混合，验证完整计划并进一步优化。GRPO 的评分由 frozen base model 自评完成，1.7B 模型则由 4B 模型评分。

实验结论可以压缩为：在 Qwen3-1.7B / 4B / 8B 上，OPSD→GRPO 的五项 benchmark 平均相对 base 分别提升 +5.56、+5.04、+4.81；反向 GRPO→OPSD 在三个规模和每个 benchmark 上都更差。Qwen3-8B 在 ResearchQA 得分 73.48，略高于论文列出的 Kimi K2.6 的 73.19。数据质量本身也重要：同一 recipe 下，PaperGym-20k 模型在 ResearchPlanGen-ML 三方比较中总体胜率 58.1%，RubricHub Science 训练模型为 28.2%，base 为 13.7%。这些数字支持“数据构造是主要增益来源之一”，但不等于 PaperGym 解决了所有研究规划评价问题。

## 四篇论文合起来的理解

四篇论文的共同公式是：学生生成自己的 $\hat y$，teacher 在更丰富的上下文中评估同一条 $\hat y$，然后用逐 token divergence 更新 student。变化在于 PI 的形态以及是否继续接结果层面的 RL：

- **OPSD**：参考答案是 hard PI；同一模型在学生自己的轨迹上做 dense token-level distillation，先证明 self-distillation 在可验证数学任务上可行。
- **RuPI**：把 hard reference 换成 soft rubric；rubric 覆盖一组可接受回答，更适合医学问答等开放式任务。
- **RCSD**：不再假定 rubric 已存在，先用 Stage I 自蒸馏出 rubric generator，再训练 rubric-guided reasoner。
- **PaperGym**：进一步解决任务和 rubric 从哪里来、怎样减少泄漏，并把同一 rubric 先用于 OPSD、后用于 GRPO，形成“分布先扩宽、奖励再收敛”的训练环境。

这条链条中，OPSD / RuPI 主要改变的是**监督接口**，RCSD 主要解决**rubric 自动化**，PaperGym 主要解决**数据构造和训练系统**。它们共享 on-policy、teacher-side privileged context 和 token-level distribution matching，但研究对象从数学答案逐步扩展到开放式科学回答，再扩展到研究计划这一更难验证的生成任务。

这也解释了一个表面上反直觉的结果：reference 在 gold completion 上的 KL 很大，训练效果却不如 rubric。训练真正优化的是 student 访问到的状态分布，而不是 gold 本身。对 hard PI 而言，最强信号可能发生在“学生不会去的地方”；对 soft PI 而言，rubric 更可能在学生当前轨迹上改变 teacher 分布。PaperGym 再把这种 dense prior 交给 GRPO 做结果层面的筛选，试图同时保留多样性和提高最终 rubric 得分。

## 思考与讨论

**一个自然的问题是，rubric 的质量门槛在哪里。** 四篇方法都依赖 teacher 能把 PI 转化为有用的分布差异；RCSD 和 PaperGym 又额外依赖 rubric generator、论文解析和 rubric scorer。第一篇已经承认，如果题目超过模型理解阈值，即使提供正确解，teacher 也未必能给出有意义的分布。第二篇进一步要求 rubric 与实际评测标准对齐；PaperGym 则显示 criterion leakage 和 rubric 质量会直接影响训练。低质量、带偏见或恶意的 rubric 会把错误的行为密集地蒸馏给学生，因此 rubric 质量检查、冲突检测和不确定性估计应成为训练前流程的一部分。

**更长的 rollout 未必更有价值。** OPSD 的数学消融表明，增加 token 数并没有稳定增益，说明训练预算更应该投向学生早期的分叉点。对 RuPI 来说也有类似启发：一个长答案后半部分往往是格式化收尾，rubric 条件化的差异很小。按 position 或 teacher–student KL 自适应地分配损失，可能比简单平均所有 token 更节省计算。

**dense PI 可能和结果级 RL、过程奖励模型互补。** Rubric 提供全局偏好，却未必指出具体事实或推理错误；PaperGym 的 OPSD→GRPO 说明，可以先用密集蒸馏建立较宽的候选分布，再用 rubric reward 做结果筛选。verifier 或 process reward model 还可以在关键步骤补充更强的局部信号。一个实际系统可以按风险选择调用更贵的 judge，而不是在所有 rollout 上使用标量 RL reward。

## AI 犀利评判

1. **四篇工作的算法增量是连续的，叙事上却容易被包装成四次范式跃迁。** OPSD 的核心是 context distillation 与 on-policy distillation 的组合；RuPI 更换 PI 类型；RCSD 加入 rubric generator；PaperGym 再加入数据构造和 GRPO 阶段。每一步都合理，但它们更像沿同一监督接口逐步扩展，而不是互不相关的全新优化原理。

2. **实验比较仍缺少训练随机性的证据。** RuPI 明确每个配置只训练一次；RCSD 和 PaperGym 的表格也主要呈现单次 recipe 的结果。评测 bootstrap 标准误不能替代不同 seed 的训练方差，因此小幅领先应谨慎解读。

3. **baseline 的公平性和预算口径需要持续留意。** RuPI 用一条 rollout 对比 GRPO 的八条 rollout；PaperGym 的 OPSD 训练 200/400 步、GRPO 训练步数和采样方式也不同。这样的设置适合展示系统效率，却不能单独证明 dense distillation 在相同 token、更新次数和 judge 调用预算下必然优于更强的 RL 配方。

4. **泛化范围仍然由 rubric 覆盖的任务决定。** RuPI 的 HealthBench / ResearchQA、RCSD 的 science reasoning、PaperGym 的 research-plan benchmark 都依赖 rubric 或 LLM judge。它们支持“可评价的开放式问答和计划生成”，还不足以支持对创意写作、多轮对话或真实科研代理的普遍结论。PaperGym 的低 criterion leakage 是数据质量进步，但不是对真实研究计划质量的直接验证。

5. **rubric generator 和自评 scorer 引入了新的误差闭环。** RCSD 用模型生成 rubric，PaperGym 又让 frozen base model 对候选计划逐 criterion 自评；生成器、teacher、scorer 之间的偏差可能被训练反复放大。PaperGym 报告了模型间一致性和 leakage，但还没有充分证明 rubric 的正确性、judge 的校准度与最终研究价值之间的因果关系。

总体判断：这组工作最可信的结论是，针对有可靠评价标准的任务，在学生自己的轨迹上保留 rubric 的分布信息，通常比单个参考答案或一个标量奖励更有训练价值；真正决定可迁移性的，仍是 rubric 质量、评估器可靠性和训练预算是否公平。
